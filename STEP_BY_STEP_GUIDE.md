A comprehensive guide explaining the setup, code changes, file structure, and step-by-step lifecycle of the **PAYSAFE AI** UPI Transaction Fraud Risk Detection academic prototype.

## 1. Code Changes Made & Why

### Modified File: `generate_data.py`
In the original version of [`generate_data.py`](generate_data.py), line 38 attempted to write directly to `"data/transactions.csv"`:

```python
# --- BEFORE ---
out = "data/transactions.csv"
df.to_csv(out, index=False)
```

#### Why it needed a change:
On a fresh download or clone of the repository, the `data/` folder does not exist. Calling `df.to_csv("data/transactions.csv")` immediately crashes Python with:
```text
FileNotFoundError: [Errno 2] No such file or directory: 'data/transactions.csv'
```

#### Fix Applied:
Added an automatic directory creation check using Python's built-in `os` module:

```python
# --- AFTER ---
import os
os.makedirs("data", exist_ok=True)
out = "data/transactions.csv"
df.to_csv(out, index=False)
```

With `os.makedirs("data", exist_ok=True)`, Python ensures the `data/` directory exists before writing the file.

## 3. Step-by-Step Execution Guide

### Step 1: Create Virtual Environment

On Windows, type `py -m venv .venv` (using the Windows Python Launcher):

```powershell
py -m venv .venv
```

#### What happens behind the scenes:
- Windows checks for installed Python versions using `py.exe`.
- It creates an isolated directory named `.venv/`.
- It copies standard Python binaries (`python.exe`, `pip.exe`) and isolated site-packages into `.venv/`.
- **Note**: If you type `python -m venv .venv` and get `Python was not found...`, Windows is trying to launch the Microsoft Store execution alias instead of your installed Python. Always use `py` or the direct path on Windows.

---

### Step 2: Activate the Virtual Environment

In Windows PowerShell or Command Prompt:

**PowerShell:**
```powershell
.\.venv\Scripts\Activate.ps1
```
*(If PowerShell displays an execution policy error, run `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` first, or use Command Prompt: `.\.venv\Scripts\activate.bat`)*

#### What happens behind the scenes:
- Modifies your terminal session's `$env:PATH` so that `.venv\Scripts` is placed first.
- Any subsequent commands (`python`, `pip`, `streamlit`) run inside the isolated environment rather than the global system environment.

---

### Step 3: Install Required Dependencies

Run:
```powershell
pip install -r requirements.txt
```

#### What happens behind the scenes:
- Pip downloads and installs:
  - **`pandas`** (Data manipulation and DataFrame handling)
  - **`numpy`** (Numerical computing and vector math)
  - **`scikit-learn`** (Random Forest Classifier, train/test split, metrics)
  - **`joblib`** (Model persistence and serialization)
  - **`streamlit`** (Interactive web application framework)
- All packages and their sub-dependencies are installed into `.venv\Lib\site-packages\`.

---

### Step 4: Generate Synthetic Transactions

Run:
```powershell
python generate_data.py
```

#### What happens behind the scenes:
1. `generate_data.py` uses NumPy's random number generator with seed `42` for reproducible results.
2. It synthesizes **2,500 transactions** across 6 key fraud risk features:
   - `amount`: Lognormal distribution clipped between ₹10 and ₹150,000.
   - `txns_last_hour`: Poisson distribution representing transaction velocity.
   - `new_payee`: Binary flag (22% probability).
   - `new_device`: Binary flag (12% probability).
   - `night_transaction`: Binary flag (18% probability).
   - `failed_attempts`: Poisson distribution (mean 0.25).
3. Calculates a synthetic fraud probability using a logistic sigmoid equation:
   $$\text{logit} = -4.0 + 0.000025 \times \text{amount} + 0.55 \times \text{txns} + 1.1 \times \text{new\_payee} + 1.3 \times \text{new\_device} + 0.65 \times \text{night} + 0.8 \times \text{failed}$$
4. Creates `data/` and saves `data/transactions.csv`.

#### Expected Terminal Output:
```text
Created data/transactions.csv with 2500 synthetic records.
Important: labels are generated for demonstration, not actual UPI fraud data.
```

---

### Step 5: Train and Evaluate the ML Model

Run:
```powershell
python train_model.py
```

#### What happens behind the scenes:
1. Loads `data/transactions.csv`.
2. Splits data into **75% training** (1,875 samples) and **25% test** (625 samples) using stratified sampling to maintain fraud label proportions.
3. Initializes a **`RandomForestClassifier`** with:
   - `n_estimators=150` (150 decision trees)
   - `class_weight="balanced"` (adjusts weights inversely proportional to class frequencies to handle imbalanced fraud records)
   - `random_state=42`
4. Evaluates test set predictions:
   - Prints classification report (Precision, Recall, F1-Score).
   - Prints 2x2 Confusion Matrix (`True Negatives`, `False Positives`, `False Negatives`, `True Positives`).
   - Calculates `ROC-AUC` score.
5. Serializes both the fitted model and feature names into a single dictionary and writes it to `models/fraud_model.joblib`.

### Step 6: Launch the Streamlit Interactive Dashboard

Run:
```powershell
streamlit run app.py
```

#### What happens behind the scenes:
1. Streamlit spins up a local web server (default port **`8501`**).
2. It loads `models/fraud_model.joblib` into memory.
3. Renders an interactive web interface with:
   - Amount input (₹)
   - Hourly transaction count
   - New payee dropdown (Yes/No)
   - New device dropdown (Yes/No)
   - Night transaction dropdown (Yes/No)
   - Recent failed attempts counter
4. When you click **"Assess Transaction Risk"**:
   - Constructs a 1-row Pandas DataFrame matching model features.
   - Computes `predict_proba()` output for the fraud class (`0.0%` to `100.0%`).
   - Maps the score to a risk category:
     - `< 40%`: **LOW RISK** (Green)
     - `40% – 74.9%`: **MEDIUM RISK** (Orange)
     - `≥ 75%`: **HIGH RISK** (Red)
   - Evaluates heuristic explanation rules and outputs specific bulleted reasons for the score.

#### Expected Terminal Output:
```text
  You can now view your Streamlit app in your browser.

  Local URL: http://localhost:8501
  Network URL: http://<your-local-ip>:8501
```

## 5. Troubleshooting Tips

1. **`python : The term 'python' is not recognized` or Microsoft Store redirect:**
   - Solution: Use `py` instead of `python`, or run `.venv\Scripts\python.exe`.
2. **`running scripts is disabled on this system` in PowerShell:**
   - Solution: Run PowerShell as normal and execute:
     ```powershell
     Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
     ```
     Then re-run `.\.venv\Scripts\Activate.ps1`.
3. **Port `8501` already in use:**
   - Solution: Specify another port with:
     ```powershell
     streamlit run app.py --server.port 8502
     ```
